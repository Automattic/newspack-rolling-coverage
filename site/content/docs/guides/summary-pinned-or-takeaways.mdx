---
title: Summary, pinned entries, or key takeaways?
description: Choose how to tell readers where a story stands, and how often to update it.
---

A liveblog page has four places that tell readers where a story stands. They overlap, so most liveblogs need only one or two of them. This page explains what each one is for, so you can choose the ones that suit the story and keep them current.

## At a glance

| | What it is | Where you edit it | Open pages update | Best for |
| --- | --- | --- | --- | --- |
| Page introduction | Text above the feed, part of the page | The page editor | No, readers reload | What the liveblog covers |
| Summary | One box at the top of the liveblog | The liveblog's entries | Yes | Where the story stands now, in a few points |
| Pinned entries | Entries held above the others | The liveblog's entries | Yes | One update every reader needs, such as a road closure |
| Key takeaways | AI-written recap you paste into the page | The page editor | No | A first draft of a recap |

## Page introduction

Write it once, when you set up the page: a sentence or two on what the liveblog covers. It is part of the page, so changing it means updating the page, and readers who have the page open see the change only after they reload.

Keep it general enough to stay true as the story moves. Put the facts that change in the summary instead.

## Summary

Use a [summary](/docs/guides/summary/) when the facts change during the story and readers need the current picture before the timeline, such as a "What we know" box with a few bullet points.

You update it in the liveblog's entries, where you post the updates, and open pages show each change. It isn't an update itself: it doesn't send a push notification or get a "New" label. Each liveblog has one at most.

## Pinned entries

Use a [pinned entry](/docs/guides/pinned-entries/) for a single update that must stay in view, such as an evacuation order, a road closure, or a phone number for help.

Pin as few as you can. With more than one, the one edited most recently comes first, and a long stack of pinned entries pushes the latest updates down the page. Unpin an entry when it no longer applies. Pinned entries sit below the summary.

## Key takeaways

[Key takeaways](/docs/guides/ai-key-takeaways/) write a short recap of the 20 most recent entries, for an editor to check and paste into the page. They are a starting point, not something that updates itself: the pasted text is part of the page, so it changes only when you generate it again and replace it.

To keep a recap current on open pages, paste the edited takeaways into the summary instead of the page.

## Which to use

- **A breaking story that moves fast:** a page introduction and a summary. Pin only what readers need for their safety.
- **A planned event, such as a match or a festival:** a page introduction. For a match, add a score with the [Scoreboard block](/docs/blocks/scoreboard/). Add a summary if readers arrive late and need to catch up.
- **A story that runs for several days:** a page introduction and a summary. Use key takeaways to draft the summary at the start of each day.

## Keep them current

- When you post an entry that changes a fact in the summary, update the summary too. The "Updated" time in the box shows readers how recent it is.
- Check the pinned entries each time you update the summary, and unpin the ones that no longer apply.
- Before you end the liveblog, update the summary to the final picture, or trash it if the last entries say enough.
