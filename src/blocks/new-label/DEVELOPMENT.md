# New Label block: development notes

The New Label block (`newspack-rolling-coverage/new-label`) is the label a layout places in an entry to mark it as new when it arrives while the page is open. Editor code lives in `src/blocks/new-label/`. Server rendering lives in `includes/blocks/class-new-label-block.php`. The marks' lifecycle (reveal, seen, clear) lives in `src/blocks/rolling-coverage/new-entry-marks.ts`, and the tint and the label's feed-level styles in `src/blocks/rolling-coverage/style.scss`.

For how publishers use the block, see `README.md` in this directory. For where the built-in layouts place it and the placement rules, see the New label under Template structure contract in `../rolling-coverage/DEVELOPMENT.md`.

## Attributes and supports

- `content` (string, default `''`, `role: content`): the label's text, edited in place with `RichText` (`allowedFormats: []`, so plain text). Empty means the translated "New", shown as the editor's placeholder and rendered by the server.
- `visuallyHidden` (boolean, default `false`): renders the label with `screen-reader-text`, in the editor too. A visually hidden label counts as no visible label, so the entry counts as seen by how much of it is in view (`isVisibleMarker()`).
- Supports: text color, and typography (font size, line height, text alignment, font family, weight, style, letter case, letter spacing). `html` and `reusable` are off. `ancestor` limits it to a Rolling Coverage block, which also wraps a layout in the layout pattern editor.

`save` returns `null`; the block is dynamic.

## Rendering

`New_Label_Block::render_block()`:

- While an entry renders (`Rolling_Coverage_Block::is_rendering_entry()`), outputs a `<p>` with the block's wrapper attributes (the supports' classes and styles, `className`, and `screen-reader-text` when `visuallyHidden`), `hidden`, and `data-rc-new-marker` (`Entry_Bindings::NEW_MARKER_ATTR`). It renders the same on every entry, so the label never shows where the view script doesn't run, Lite Site pages included. The text is `content` with its tags stripped, escaped with `esc_html()`, or the translated "New" when that leaves nothing or only spaces (no-break spaces included). `content` is already HTML, so its entities aren't decoded: a typed `&lt;` is stored as `&amp;lt;` and renders as typed, and `esc_html()` doesn't encode an entity twice.
- In a syndication feed (`is_feed()`), renders nothing, since no script runs there to manage the label and a reader may ignore `hidden`.
- Anywhere else, such as among the coverage-level blocks or outside a feed, renders nothing.

The view script keys on `data-rc-new-marker`, not on a class or the block name: `NewEntryMarks` removes `hidden` on a new entry's own marker and sets it again once the mark clears.

## The tint

`style.scss` tints a marked entry (`data-new`) only while its own marker shows: `NewEntryMarks` sets `data-new-label` on the entry when it reveals the entry's own marker, leaving out a nested feed's, and removes it when the mark settles. So an entry whose template holds no New Label gets no tint, only the screen-reader "New" (`newspack-rolling-coverage-new-status`) that `NewEntryMarks` adds. A visually hidden label still counts, so Minute's entries are tinted. The tint is the entry's `::after`, with the entry's radius, painted beneath the entry's content: the entry gets `isolation: isolate` and the pseudo-element `z-index: -1`, so it sits above the entry's own background and below everything in it, whether the color is translucent or opaque. Its color is `--newspack-rolling-coverage-new-tint`, set on the Rolling Coverage block's root to 50% of `base-2` (`--wp--preset--color--base-2`, else `--newspack-theme-color-bg-light`, else `#f0f0f0`) over transparent. It fades with the label over `$clear` on `$ease` when `data-new` becomes `clearing`. An entry whose entry group is laid out as a row in a row Feed, as Flash's are, gets no tint (`content: none` on the `::after`): Flash sets its entries on the accent-filled bar, where a pale box across the text reads as a selection, so the label, in the bar's text color, marks the entry alone. The rule keys on that structure rather than the layout's slug, so it holds for a detached or custom layout built the same way. Ticker's entries stack inside a row Feed on the page's own background, so they keep the tint.

The tint fills the entry's row, from separator to separator, so its top and bottom come from the layout rather than the entry's own box: in Clock or Digest the entry starts at its separator and ends at its last line, in Bulletin it ends at its separator, and the gap between entries is outside every entry. `NewEntryMarks` measures it when it reveals the marker (`placeTints()`), again for the labeled entries beside it, whose neighbor changed, and for every labeled entry, once a frame, when the window resizes or an entry list gains or loses a child (an entry pinned, loaded or taken down while the page is open), and sets `--newspack-rolling-coverage-new-tint-start` and `-end` on the entry for the pseudo-element's `inset-block`; settling the mark removes them. `rowEdges()` finds the lines at the entry's top and bottom edges: a separator block there (one `style.scss` hides, as above a pinned card or Full Story Entry, has no height and doesn't count), or a box spanning the entry's width with a border on that edge only; it skips the entry's text and nested feeds, and takes a box running the entry's full height with a background color or image or a border all around as a card, whether it is as wide as the entry or takes at least half of it in one of its columns, as Rail's cards do. It searches six levels down from the entry, so a custom layout that nests its card deeper gets the halfway reach. `tintInsets()` then places each edge: an edge with its own line stops at it; one facing a neighboring entry's line, or a card such as a pinned entry or a Full Story Entry, reaches across the gap to it, flush; one facing a neighbor with neither, or something shown between them other than an entry, such as an ad, reaches halfway, so two tinted rows meet mid-gap; the first and last entries mirror the other rows (across the gap when the entry has a line on its other edge, halfway otherwise). A card keeps the tint inside it, and a layout that places entries side by side (Ticker) keeps `inset-block: 0`. The gap is the layout's `row-gap`. The arrival's clip reaches a gap past the entry, so the tint shows while the entry's space opens. A card with its own opaque background, such as a pinned card, hides the tint entirely, since the tint paints beneath the card; only the label shows there.

The tint also bleeds past the entry's left and right sides, so it doesn't hug the text like a selection: by `--newspack-rolling-coverage-new-tint-bleed`, set on the block's root to the `30` spacing preset (`--wp--preset--spacing--30`, else `1rem`), but never further than the room `placeTints()` measures beside the entry, up to the viewport's edge or an ancestor that clips its overflow (`tintRoom()`), and sets as `--newspack-rolling-coverage-new-tint-room-left` and `-right`. The pseudo-element's `left` and `right` take the smaller of the two, so on a phone, where the page's gutter is often narrower than the bleed, the tint stops at the screen's edge rather than scrolling the page sideways. Physical sides, rather than `inset-inline`, since the room is measured on the screen. Until it is measured, the room is 0 and the tint is flush with the entry. A card and a layout that places entries side by side get no room, so the tint stays inside the card and off the neighbors beside the entry. The room is measured whenever the top and bottom are, so it follows a resize. No text moves, since the pseudo-element is out of flow.

## Editor

- `RichText` has `disableLineBreaks`, so the label stays on one line. While `content` is empty, `editor.scss` shows the "New" placeholder at full strength rather than core's dimmed placeholder, so the canvas matches the site; the text isn't stored, so it follows the site's language.
- `newLabel()` in `template.ts` builds the block for the built-in layouts: `use-header-font`, the `small` font size, weight 700, the readable accent as the text color unless `color: null` (Flash), an optional text alignment, and `visuallyHidden` for Minute. It leaves `content` empty, so the layouts' server copies carry no text to translate.
- `isNewLabel()` matches the block by name (`NEW_LABEL_BLOCK_NAME`). `withoutNewLabel()` (`layout.ts`'s previews) and `hiddenNewLabelIds()` (`edit.tsx`) use it to show the label only on the sample previewing the newest unpinned entry.
- `ENTRY_ALLOWED_BLOCKS` (`template.ts`) lets the block into the Feed group.

## Tests

`tests/test-new-label-block.php` covers the label rendering hidden and tagged on regular, pinned and Full story entries, custom text escaped with its entities as typed, empty or space-only text giving "New", Visually hidden, syndication feeds, and rendering outside an entry. `tests/js/new-label-hiding.test.ts` covers `hiddenNewLabelIds()`, and `tests/js/layout-templates.test.ts` the built-in layouts' placements. `tests/js/new-entry-marks.test.ts` covers the marks' lifecycle, marking in batches (`markAll()`, `data-new-label`, `release()`), and the tint's measured insets and side room (`rowEdges()`, `tintInsets()`, `tintRoom()`) and when they are placed again; the tint's paint is CSS and isn't tested there.
